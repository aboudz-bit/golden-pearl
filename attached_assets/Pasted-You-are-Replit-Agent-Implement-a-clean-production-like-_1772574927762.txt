SCOPE
- The client can use the website and mobile web app without signing in (guest mode).
- Login is REQUIRED only when the user proceeds to payment/checkout.
- After login, the user’s existing guest basket (cart) and likes (favorites/wishlist) must NOT be lost. They must merge into the user account and continue to persist across refreshes and future sessions.

PART A — AUTH + GUEST MODE + DATA PERSISTENCE
1) Guest browsing:
   - Allow full browsing: categories, product details, search, add-to-cart, favorites.
   - No login prompts during browsing.
2) Login requirement:
   - Enforce login only at: “Pay / Place Order / Checkout”.
   - If guest clicks Pay, open login modal/screen. After success, resume checkout without losing state.
3) Persistence rules:
   - Guest cart & favorites persist locally (localStorage) across refresh.
   - Logged-in cart & favorites persist per-user (localStorage keyed by userId OR DB if present).
4) Merge logic (critical):
   - On successful login:
     - Merge guestCart into userCart:
       - For identical product+variant, sum quantities (or prefer max) and avoid duplicates.
     - Merge guestFavorites into userFavorites (set union).
     - Then clear guestCart/guestFavorites keys so future guest sessions start clean.
   - Ensure the UI immediately reflects merged results (cart count, favorites icons).
5) Multi-device note:
   - If you already have a backend DB, store user cart/favorites server-side; otherwise keep client-side but properly keyed by userId.
   - Do NOT lose data when switching routes or refreshing.
