Add Password Recovery (Forgot/Reset Password) for Customer, Admin, and Staff using Email OR Phone.

Goal:
All user roles (Customer / Admin / Staff) must be able to recover access if they forget their password, using either:
- Email (OTP code)
- Phone number (OTP code via SMS)

Scope:
Applies to BOTH:
1) Customer app login
2) Admin/Staff login

UI/UX (Flutter):
1) On Login screen add: "Forgot password?"
2) Tapping opens a new screen with:
   - Choice tabs or segmented control: Email | Phone
   - Input field (email or phone)
   - Button: "Send Code"
3) After sending code, navigate to OTP screen:
   - Enter 4-6 digit code
   - Button: "Verify"
4) After OTP verified, navigate to Reset Password screen:
   - New Password
   - Confirm Password
   - Button: "Reset Password"
5) On success:
   - Show success snackbar
   - Redirect to Login screen
6) Add cooldown timer:
   - Resend code disabled for 60 seconds

Backend (Express):
Implement OTP-based reset flow with these endpoints:

1) Request OTP
POST /auth/password-reset/request
Body:
{
  "channel": "email" | "phone",
  "email": "user@example.com",        // if channel=email
  "phone": "0551234567"               // if channel=phone
}

Behavior:
- Find user by email OR phone across all roles (customers/admin/staff)
- If user exists: generate OTP (6 digits), hash it, store in DB with:
  userId, channel, otpHash, expiresAt (10 minutes), attempts, createdAt
- Return 200 always (do NOT reveal if user exists)
- Send OTP:
  - Email: send via email provider (SendGrid/Mailgun/etc)
  - Phone: send via SMS provider (Twilio/Unifonic/Mobily/etc)
- Rate limit per identifier (email/phone):
  max 3 requests per 15 minutes

2) Verify OTP
POST /auth/password-reset/verify
Body:
{
  "channel": "email" | "phone",
  "email": "user@example.com",
  "phone": "0551234567",
  "otp": "123456"
}

Behavior:
- Validate OTP (hash compare)
- Check expiry
- Track attempts (lock after 5 attempts)
- If valid: issue a short-lived resetToken (JWT or random token stored in DB)
Return:
{
  "resetToken": "....",
  "expiresIn": 900
}

3) Reset Password
POST /auth/password-reset/confirm
Body:
{
  "resetToken": "...",
  "newPassword": "StrongPass123!"
}

Behavior:
- Validate resetToken and expiry
- Hash password (bcrypt)
- Update user's password
- Invalidate all active sessions for that user (logout everywhere)
- Delete/expire OTP records and reset token

Database:
Add table password_reset_otps:
- id
- userId
- channel (email/phone)
- target (email or phone)
- otpHash
- expiresAt
- attempts
- createdAt

Add table password_reset_tokens (or reuse same table):
- id
- userId
- tokenHash
- expiresAt
- createdAt
- usedAt

Security Requirements:
- OTP expires in 10 minutes
- Reset token expires in 15 minutes
- Never reveal if email/phone exists
- Rate limiting enabled
- OTP attempts limited to 5
- Use hashed OTP and hashed tokens in DB (never store raw)
- Phone normalization (E.164) or consistent KSA format validation
- Audit log: password reset requested, verified, completed (without storing OTP)

Acceptance:
✔ Customer/Admin/Staff can reset password by Email OR Phone
✔ OTP sent and verified
✔ Password updated securely
✔ Sessions invalidated after reset
✔ Rate limits + attempt limits enforced
