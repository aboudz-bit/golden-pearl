PHASE 1 — PROJECT STRUCTURE REFACTOR (CLEAN ARCHITECTURE)
========================================================
A) FRONTEND (Flutter)
Restructure into a predictable layout:

lib/
  app/                 (app bootstrap, routes, localization wiring)
  core/                (constants, helpers, shared base classes)
  theme/               (colors, typography, spacing)
  models/              (plain models)
  services/            (ApiService, storage/cache, upload service)
  state/               (providers, notifiers, stores)
  features/
    home/
    products/
    categories/
    cart/
    checkout/
    orders/
    admin/
    settings/
  widgets/             (shared reusable widgets)

Rules:
- Move API calls into services only.
- Move stateful logic into state/ (Provider/ChangeNotifier/etc).
- UI screens should be thin: call state/services, render widgets.
- Remove duplicate widgets; create shared components.

B) BACKEND (Node/Express)
Restructure into:

server/
  index.ts             (app bootstrap)
  config/              (env, constants)
  routes/              (route registration only)
  controllers/         (req/res handlers, minimal logic)
  services/            (business logic)
  middleware/          (auth, admin gate, validation, rate limit)
  storage/             (db access layer)
  utils/               (helpers)
  types/               (shared types)

Rules:
- Routes must not contain business logic.
- Controllers should be thin: validate -> call service -> respond.
- Services call storage layer; storage talks to DB.
- Remove duplicate functions; unify patterns.

PHASE 3 — ERROR HANDLING + RESPONSE STANDARDIZATION
========================================================
Backend:
1) Implement centralized error middleware:
- All controllers should throw typed errors (or call next(err)).
- Standard JSON error format:
  {
    "success": false,
    "message": "Human readable",
    "code": "SOME_CODE",
    "details": optional
  }

2) Standardize success responses:
  {
    "success": true,
    "data": ...
  }

3) Make sure ALL async routes have try/catch or are wrapped in an asyncHandler helper.

Frontend:
- ApiService must:
  - handle non-200 responses safely
  - parse error JSON
  - return typed exceptions
- UI screens must show friendly error messages and never crash silently.

PHASE 6 — FILE UPLOAD SAFETY (CRITICAL)
========================================================

- Serve via express.static with safe headers

- Add simple anti-abuse:
  - Rate-limit upload endpoints
